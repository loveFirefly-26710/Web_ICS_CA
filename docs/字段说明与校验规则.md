# 字段说明与校验规则

界面上每个输入框下面显示的就是这份内容。它由 `internal/validate` 的 `Catalog()` 通过
`/api/spec` 提供给界面，实际校验用的是同一批规则函数。

这份文档与 `Catalog()` 是手工保持一致的：改了代码里的说明表，记得回来同步这里。

> 核对方法：起一次服务，打开 `/api/spec`，返回的 `fields` 数组就是界面上的全部字段说明。
> 也可以直接跑 `audit-workspace/script-output/dump_spec.js` 把它导出成 JSON 再逐条对。

---

## 字段总表

| 键 | 界面标签 | 分组 | 必填 | 校验函数 |
|---|---|---|---|---|
| `ca_name` | CA 名称 | 根 CA | 是 | `validate.CAName` |
| `ca_days` | CA 有效期 | 根 CA | 是 | `validate.Days` |
| `server_cn` | 服务器名（CN） | 服务器证书 | 是 | `validate.ServerCN` |
| `server_internal` | 内网地址 | 服务器证书 | 否 | `validate.AddressList(..., false)` |
| `server_external` | 外网地址 | 服务器证书 | 否 | `validate.AddressList(..., true)` |
| `server_days` | 服务器证书有效期 | 服务器证书 | 是 | `validate.Days` + `validate.NotAfterCA` |
| `client_cn` | 终端名（CN） | 客户端证书 | 是 | `validate.ClientCN` |
| `client_org` | 归属（O） | 客户端证书 | 否 | `validate.Org` |
| `client_days` | 客户端证书有效期 | 客户端证书 | 是 | `validate.Days` + `validate.NotAfterCA` |
| `pfx_password` | 证书包密码 | 客户端证书 | 否 | `validate.PFXPassword` |
| `out_dir` | 输出目录 | 全局 | 是 | 服务端检查（见文末） |

「键」这一列就是界面上的对应关系：输入框下面的帮助文本用 `data-help="<键>"` 找，
错误提示用 `data-err="<字段名>"` 找。对不上的话界面上不会显示任何提示，也不会报错。

## 根 CA

### `ca_name` · CA 名称

**用途** 这套内部 CA 的名字。它只是给人看的标识，会写进证书的 Subject，客户端装证书时能靠它
认出「这是谁签的」。

**格式** 1–64 个字符，可用中英文、数字、空格、点、连字符、下划线、括号

**示例** 我的文档站 CA

**必填** 是

**校验规则**

- 必填，长度 1–64
- 不能以空格开头或结尾
- 不能包含控制字符，以及 `/ \ , " ' = @ :` 这些会破坏日志或 Subject 的字符

### `ca_days` · CA 有效期

**用途** CA 证书从签发日算起能用多少天。所有由它签出的证书，有效期都不能超过它。CA 一过期，
它签出去的全部证书立刻失效，所以这个值要留足。

**格式** 整数天数，1–7300

**示例** 3650（10 年）

**必填** 是

**校验规则**

- 必填，整数
- 范围 1–7300
- 换 CA 比换服务器证书麻烦得多，建议不小于 3650

## 服务器证书

### `server_cn` · 服务器名（CN）

**用途** 服务器证书的主体名。现代浏览器校验证书时只看 SAN、不看 CN，所以这个值主要是给人看的
标识，以及在没有 SAN 时的兜底。填服务对外的主机名最省事。

**格式** 1–64 个字符，主机名、IP 或一个便于识别的中文名

**示例** docs.example.com

**必填** 是

**校验规则**

- 必填，长度 1–64
- 不能以空格开头或结尾
- 不能包含控制字符，以及 `/ \ , " ' = @ :`
- 真正决定浏览器认不认的是下面的内网 / 外网地址，别只填这一个框

### `server_internal` · 内网地址

**用途** 局域网里访问这台服务用的地址。填 IP 就进证书的 IP 字段，填名字就进 DNS 字段，
两种都支持，按你实际在浏览器里敲的那个填。一台机器在内网可能有多个入口，所以可以写多行。

**格式** 每行一个，IPv4 / IPv6 或主机名

**示例** `192.168.1.10` ／ `nas.lan` ／ `docs`

**必填** 否

**校验规则**

- 可选，但内网地址与外网地址至少要填一个
- 每行一个，不要写端口、路径、协议前缀
- 是 IP 就按 IP 校验；否则按主机名校验，允许单段名（如 `nas`）
- 同一份证书里不能重复

### `server_external` · 外网地址

**用途** 从公网访问这台服务用的域名。填了它，别人用这个域名打开时浏览器才不会报证书不受信任。
没有公网入口就留空。

**格式** 每行一个完整域名

**示例** `docs.example.com` ／ `www.example.com`

**必填** 否

**校验规则**

- 可选，但内网地址与外网地址至少要填一个
- 必须是有至少两段的完整域名，不接受单段名
- 不能带协议前缀、端口、路径
- 不支持通配符（`*.example.com`）

### `server_days` · 服务器证书有效期

**用途** 服务器证书能用多少天。到期后浏览器会直接拒绝连接，需要重新签发并替换。

**格式** 整数天数，1–3650

**示例** 365

**必填** 是

**校验规则**

- 必填，整数，范围 1–3650
- 不能超过 CA 的剩余有效期

## 客户端证书

### `client_cn` · 终端名（CN）

**用途** 客户端证书的主体名，代表一台设备或一个人。服务端把「有证书」等同于「有权访问」，
这个值不参与授权判断，只作为日志里的身份显示名，所以起个一眼能认出来的名字最有用。

**格式** 1–64 个字符，设备名、人名都行

**示例** 我的手机 ／ 张三的笔记本

**必填** 是

**校验规则**

- 必填，长度 1–64
- 不能以空格开头或结尾
- 不能包含控制字符，以及 `/ \ , " ' = @ :`
- 同一个人有多个设备时建议带后缀区分，吊销时才好定位

### `client_org` · 归属（O）

**用途** 写进证书 Subject 的 Organization 字段。用于把终端按部门或项目分组，证书多起来之后
靠它筛。不填就不写这一项。

**格式** 0–64 个字符

**示例** 运维部

**必填** 否

**校验规则**

- 可选
- 长度不超过 64
- 字符限制同终端名

### `client_days` · 客户端证书有效期

**用途** 客户端证书能用多少天。客户端证书是设备丢失后的主要风险点，有效期短一些更安全，
到期重新签一张即可。

**格式** 整数天数，1–3650

**示例** 365

**必填** 是

**校验规则**

- 必填，整数，范围 1–3650
- 不能超过 CA 的剩余有效期

### `pfx_password` · 证书包密码

**用途** 导出 `.pfx` 时给私钥加密用的密码。Windows 双击导入 `.pfx` 会要求输入它。
只导出 PEM 的话用不到。

**格式** 6 位以上

**示例** 自己定一个，记牢

**必填** 否（勾了「同时导出 .pfx」就变成必填）

**校验规则**

- 导出 `.pfx` 时必填，长度至少 6
- 不导出 `.pfx` 可以留空
- 这个密码只是保护文件本身，忘掉就只能重新签发

## 全局

### `out_dir` · 输出目录

**用途** 签发出的证书、私钥、配置片段都写到这个目录。建议单独建一个，不要和文档库混在一起，
这里面有私钥。

**格式** 目录路径，相对路径按程序工作目录展开

**示例** `./ics-certs`

**必填** 是

**校验规则**

- 必填
- 目录不存在时会自动创建
- 目录必须可写，否则签发会失败

这个字段不在 `internal/validate` 里校验，它在服务端的 `handleSettings` 里走三步：
判空 → 转绝对路径 → 建目录 → **试写一次**。最后一步不能省，目录建得出来不代表能写
（只读挂载、权限不足都要到写的时候才暴露），而设置一个写不了的目录，问题会拖到用户点签发
才出现。

转成绝对路径之后才会存进状态文件。程序可能从不同工作目录启动，存相对路径的话下次会解析到
别的地方。

## 这些规则为什么长这样

挑几条不那么显然的说一下，省得以后有人想「简化」掉它们。

**为什么内网地址允许单段名、外网地址不允许。**
`intranet` 这种名字靠 DNS 搜索域补全，只有内网环境解析得了；证书里写一个公网解析不了的名字
没有意义。内网环境里用单段名访问很常见，所以放行。

**为什么报错要拦协议前缀、端口、路径。**
`https://docs.example.com:8443/path` 是 URL，不是主机名。用户从浏览器地址栏复制过来时经常
带上这些，直接写进 SAN 会得到一个永远匹配不上的证书。浏览器不会报错，只是安静地判定证书无效。
所以宁可在这里拦下来，说清去掉哪一段。

**为什么子证书的有效期要卡在 CA 之内。**
签发者过期之后，它签出的证书全部失效，即使那些证书自己的有效期还没到。这种故障很难查：
证书看着完好、日期也对，浏览器却一律拒绝。所以在签发时就拦住。

**为什么客户端证书的 `KeyUsage` 一定要有 `digitalSignature`。**
只有 `extendedKeyUsage` 时，Windows 的证书选择器可能不认这张证书，浏览器根本不会把它递出去。
服务端收到的是没有证书的握手，页面显示「需要客户端证书」，从现象上完全看不出问题出在签发环节。

**为什么 CA 名称、终端名禁止 `/ \ , " ' = @ :` 这些字符。**
它们要么会破坏 `pkix.Name` 的字符串编码，要么会让日志里的身份显示串产生歧义
（服务端日志会记录证书的 Subject）。名字是给人看的，不值得为这几个字符冒风险。

**为什么地址要去重。**
同一份证书里出现两条一样的 SAN 没有意义，而且会让「覆盖了哪些地址」变得难读。冲突时把两条
原样报出来，用户才知道删哪条。

**为什么「至少填一个地址」的错误挂在内网字段上。**
内网与外网都合法、但两边加起来一个地址都没有时，总得把错误挂到某个字段上。挂在内网，
因为用户最可能在那里补。这条只在两边都没报错时才判，否则用户会同时看到两条互相矛盾的提示。
