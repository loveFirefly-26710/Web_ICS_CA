# 开发文档

面向要改这个项目的人。讲清楚它由哪几块组成、每块的职责边界、以及改动时要一起动的地方。

---

## 一、项目目标

给 [Web_ICS](https://github.com/loveFirefly-26710/Web_ICS) 提供一套图形化的内部证书签发工具。

web_ics 支持客户端证书认证（mTLS），但开启它需要在服务器上手工执行一串 openssl 命令：
建 CA、签服务器证书、给每台设备签客户端证书、导出浏览器能装的证书包、维护吊销名单。
命令长、参数多、错一步要到浏览器握手失败时才发现。

这个工具把那串命令做成界面：

- 一张内部 CA，签服务器证书和客户端证书；
- 客户端证书可以顺带导出 `.pfx`，Windows 上双击就能装进证书库；
- 吊销名单以纯文本维护，格式与 web_ics 的解析口径一致；
- 最后生成可以直接贴进 `web_ics.conf` 的配置片段。

交付形态是一个单文件 Windows EXE。双击就打开自己的窗口，不需要装运行时（除了系统自带的
WebView2），也不联网。

**不做什么**：不替代 web_ics，不碰 web_ics 的代码，不提供在线服务。它只按约定产出文件，
剩下的事（把文件放哪、重启服务）由使用者做。

## 二、整体架构

单个进程，三块东西：

```
┌─────────────────────────────────────────────────────────────┐
│ web-ics-ca.exe                                              │
│                                                             │
│  ┌──────────────┐   HTTP（127.0.0.1，端口随机）  ┌─────────┐  │
│  │  WebView2    │◀─────────────────────────────▶│ 内置服务 │  │
│  │  窗口        │        cookie: ca_session     │         │  │
│  └──────────────┘                                └────┬────┘  │
│         ▲                                             │       │
│         │ 内嵌资源（go:embed ui）                      │       │
│         └─────────────────────────────────────────────┘       │
│                                                       │       │
│                                    ┌──────────────────▼────┐  │
│                                    │ internal/app          │  │
│                                    │ internal/certs        │  │
│                                    │ internal/validate     │  │
│                                    └───────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

几个刻意的选择：

**界面是本地网页，不是原生控件。** 签发这件事的本质是「填字段、按一下、拿到几个文件」，
用网页做最省事，改样式不用重编译。网页用 `go:embed` 打进二进制，所以产物仍然是单文件。

**服务只监听 127.0.0.1，端口由系统挑。** 外面进不来。端口不固定是因为固定端口会在重复启动、
端口被占用时失败，而服务本来就只给本机的一个窗口用。

**窗口是内嵌 WebView2，不借 Edge 的外壳。** 借 `msedge --app=` 也能得到一个没有地址栏的窗口，
但任务栏和窗口上仍是 Edge 的样子，进程也不是自己的。

**证书库每次扫磁盘，不存索引。** 索引与磁盘不同步是最难查的一类问题：界面说证书在，
服务端说验不过。现在列表永远反映目录里真实有什么。

## 三、模块划分

| 目录 | 职责 | 依赖 |
|---|---|---|
| `internal/certs` | 证书领域逻辑：建 CA、签发、解析、导出 PKCS#12、吊销名单格式化、扫描目录 | 只依赖标准库与 `go-pkcs12` |
| `internal/validate` | 全部字段校验规则，以及给界面用的字段说明表 | 只依赖标准库 |
| `internal/app` | HTTP 服务、会话令牌、证书库状态组装、状态文件读写、配置片段生成 | 依赖上面两个 |
| `ui/` | 界面（HTML/CSS/JS，无框架无构建步骤） | 运行时通过 HTTP 拿数据 |
| 根目录 `*.go` | 入口与平台相关的壳：窗口、DPI、单实例、消息框、打开浏览器 | 只被 `main` 用 |

分层规则很简单：**`certs` 不认识 HTTP，也不认识界面**；`app` 把 `certs` 包成接口暴露给前端。
要加一个新的签发能力，落点应该在 `certs`，`app` 只做参数搬运和错误翻译。

### `internal/certs` 文件划分

| 文件 | 内容 |
|---|---|
| `types.go` | 包说明、`Kind`、`CertInfo`、`CA`、`ServerRequest`、`ClientRequest` |
| `keys.go` | 密钥生成、序列号、PEM 编解码、写文件、文件名清洗、重名避让 |
| `ca.go` | 建 CA、加载 CA（含自检）、导入 CA、PEM 解析 |
| `issue.go` | 签服务器证书、签客户端证书、公共签发后半段、公钥配对校验 |
| `pfx.go` | 导出 PKCS#12 |
| `inspect.go` | 指纹计算、`x509.Certificate` → `CertInfo` |
| `scan.go` | 扫目录、定位 CA、判定角色、角色标签 |
| `deny.go` | 吊销名单的数据结构与格式化 |

## 四、关键技术选型

### 语言与证书库

**Go 1.25 + 标准库 `crypto/x509`。** web_ics 本身是 Go，签发逻辑用标准库写就是几十行，
而且能直接复用 ICS 仓库里已经跑通的证书参数。产物是单文件 EXE，没有运行时依赖。

**RSA 2048，不是 ECDSA。** 和 web_ics README 里那套 openssl 命令对齐。
客户端证书最终要装进 Windows 证书存储，RSA 在那里的兼容性最稳。

**签名算法**：证书走 `sha256WithRSAEncryption`。`KeyUsage` 只给 `digitalSignature`：
web_ics 走 ECDHE 密钥交换，不需要 `keyEncipherment`。

### 第三方依赖

只有三个直接依赖，都能说清为什么需要：

| 模块 | 用途 | 为什么不自己写 |
|---|---|---|
| `software.sslmate.com/src/go-pkcs12` | 导出 `.pfx` | 标准库不提供 PKCS#12 编码 |
| `github.com/jchv/go-webview2` | 内嵌窗口 | 需要 COM 与 WebView2 运行时的完整封装 |
| `golang.org/x/sys` | Win32 调用 | `windows` 与 `registry` 子包比手写 `syscall` 清楚 |

间接依赖两个：`go-winloader`（go-webview2 用）、`golang.org/x/crypto`（pkcs12 用）。

**PKCS#12 用 `Modern` 而不是 `Legacy`**：PBES2 + AES-256-CBC + SHA-256。老式的 RC2/3DES 方案
在 Windows 上会被塞进「Microsoft Enhanced Cryptographic Provider」，浏览器可能递不出证书。

### 界面

原生 HTML/CSS/JS，没有框架、没有构建步骤。原因：这个界面只有七个页签、十几个输入框，
引入构建链的收益抵不上维护成本。

**校验规则不在前端。** 输入框一变就调 `/api/validate` 问服务端，规则只有 `internal/validate`
那一份。这样「界面上说的」和「程序判的」不可能不一致。

### 平台相关代码

平台差异一律用 `//go:build` 分成一对文件，而不是在函数里写 `runtime.GOOS` 分支：

| 能力 | Windows | 其他 |
|---|---|---|
| 窗口 | `window_windows.go`（WebView2） | `window_other.go`（空实现，退回浏览器） |
| DPI 感知 | `dpi_windows.go` | `dpi_other.go`（空实现） |
| 单实例 | `singleinstance_windows.go`（互斥体） | `singleinstance_other.go`（恒为真） |
| 错误框 | `msgbox_windows.go`（MessageBoxW） | `msgbox_other.go`（打 stdout） |
| 打开界面 | `openbrowser_windows.go`（Edge 应用模式 / 默认浏览器） | `openbrowser_other.go`（open / xdg-open） |

非 Windows 平台没有内嵌窗口，启动流程会退回系统浏览器。`build.sh` 里那一步 Linux 交叉编译
就是用来确认这些分支还能编过的。

## 五、接口与数据结构约定

### 5.1 HTTP 接口

服务只监听回环地址。除首页与静态资源外，每个接口都要带会话令牌：

- 启动时随机生成 24 字节，十六进制编码后放在 cookie `ca_session` 里；
- 首页接受 `?t=<令牌>`，命中就把令牌种进 cookie；
- `/api/` 下的请求由 `withAuth` 校验，用 `subtle.ConstantTimeCompare` 比较。

| 方法 | 路径 | 入参 | 出参（`data` 内） |
|---|---|---|---|
| GET | `/api/spec` | — | `{fields: [FieldSpec]}` |
| GET/POST | `/api/state` | — | `stateResp` |
| POST | `/api/validate` | `{form, cn, org, name, internal[], external[], days, pfxPassword, exportPfx}` | `{errors: {字段名: 文案}}` |
| POST | `/api/settings` | `{outDir}` | `stateResp` |
| POST | `/api/ca` | `{action: "create"\|"import", name, days, certPath, keyPath}` | `{ca: CertInfo, state: stateResp}` |
| POST | `/api/issue/server` | `serverForm` | `{cert: CertInfo, state}` |
| POST | `/api/issue/client` | `clientForm` | `{cert: CertInfo, state}` |
| POST | `/api/revoke` | `{fingerprint, note}` | `stateResp` |
| POST | `/api/unrevoke` | `{fingerprint}` | `stateResp` |
| POST | `/api/export/deny` | — | `{path, count}` |
| POST | `/api/conf` | `{serverCertPath}` | `{snippet, warnings[]}` |
| POST | `/api/reveal` | `{path}` | `{path}` |
| POST | `/api/quit` | — | `{message}` |

响应统一两种形状：

```json
{"ok": true,  "data": { ... }}
{"ok": false, "error": "给人看的说明"}
```

字段级校验失败时多一层 `fields`，界面按它把对应输入框标红：

```json
{"ok": false, "error": "有几项需要修改", "fields": {"cn": "服务器名不能为空"}}
```

**改接口时要一起改的地方**：`ui/app.js` 的 `api()` 调用点、`handleAPI` 里的 switch、
以及本文档的这张表。

### 5.2 数据结构

**`CertInfo`** 是界面展示一张证书所需的全部信息，也是 `/api/state` 里证书行的形状：

```go
type CertInfo struct {
    Kind        Kind      // ca / server / client
    CN, Org     string
    Serial      string
    NotBefore   time.Time
    NotAfter    time.Time
    DNSNames    []string
    IPs         []string
    Fingerprint string    // SHA-256，小写十六进制，吊销名单的主键
    CertPath    string
    KeyPath     string    // 同名 .key 不存在时为空
    PFXPath     string
}
```

字段与 `ui/app.js` 的渲染一一对应。加字段时那边要跟着用起来，否则是死数据。

**`stateResp`** 是界面渲染一次所需的全部数据。注意两个 slice 都显式初始化成空切片而不是留 `nil`：
`nil` 会被 JSON 编码成 `null`，界面那边就得多写一层判空。

```go
type stateResp struct {
    OutDir, StorePath, Version string
    CA    *certRow          // 没有 CA 时为 null
    Certs []certRow         // certRow = CertInfo + label/revoked/expired/daysLeft
    Deny  []certs.DenyEntry
    Conf  confResp          // {snippet, warnings}
}
```

**`FieldSpec`** 是字段说明表，同时喂给界面和 `docs/字段说明与校验规则.md`：

```go
type FieldSpec struct {
    Key, Label, Group       string
    Purpose, Format, Example string
    Required                bool
    Rules                   []string
}
```

`Key` 必须与 `ui/index.html` 里 `data-help="..."` 的取值一致。对不上的字段界面上不会显示任何提示，
也不会报错，属于静默失效。

**`ConfInput`** 是生成配置片段需要的四项事实。空值不会被跳过，而是渲染成一行注释，
让用户看得见缺什么：

```go
type ConfInput struct{ CAPath, ServerCertPath, ServerKeyPath, DenyPath string }
```

### 5.3 文件命名约定

| 文件 | 命名规则 |
|---|---|
| CA 证书 / 私钥 | 固定 `ca.crt` / `ca.key`，扫描与导入都靠这两个名字定位 |
| 子证书 | `<名字>.crt` / `<名字>.key`，名字由 `fileBase()` 清洗 |
| 证书包 | `<名字>.pfx`，只有勾了导出才生成 |
| 吊销名单 | `deny.txt` |

`fileBase()` 的清洗顺序：去掉控制字符，把 Windows 非法字符 `/\:*?"<>|` 换成 `-`，
去掉首尾空白与点，合并连续的 `-`，按 rune 截到 64 个字符，全空时退回 `cert`。

**重名不覆盖**：`uniquePath()` 会依次试 `<名字>-2.crt`、`-3`……最多到 `-999`。
覆盖的后果很隐蔽：私钥被换掉、旧证书还在某台设备上装着，两边指纹对不上，
排查时没有任何线索指向签发环节。

### 5.4 吊销名单格式

与 web_ics 的 `auth.go` 解析口径绑定：

```
# web_ics 客户端证书吊销名单
sha256:2f8a...e41 我的手机
```

一行一个 `sha256:<64 位小写十六进制>`，后面可以跟空格分隔的备注，`#` 开头是注释。
输出前按指纹排序，保证同一份名单每次写出的字节一致（名单要进版本库、要 diff）。
格式对不上时 web_ics 会把整份名单判成非法并拒绝启动。

## 六、配置项

### 6.1 命令行参数

| 参数 | 默认 | 作用 |
|---|---|---|
| `--out-dir <路径>` | 空 | 指定证书输出目录并记住它，下次启动直接用 |
| `--browser` | false | 不建内嵌窗口，改用系统浏览器 |
| `--no-open` | false | 只起服务并打印地址，不打开任何界面（脚本用） |
| `--version` | — | 打印版本号后退出 |

### 6.2 状态文件

`web-ics-ca.json`，只记两样东西：上次用的输出目录、当前吊销名单。

存放位置：优先 exe 同目录（便携用法：整个目录拷走，设置跟着走）；该目录不可写时退回
`os.UserConfigDir()` 下的 `Web_ICS_CA/`。判断可写靠真建一个临时文件试，不看权限位。

证书本身不存在这里，永远以磁盘为准。状态文件解析失败会直接报错退出，不静默重置：
里面带着吊销名单，悄悄丢掉它等于悄悄放行一批本该被拒的证书。

### 6.3 生成的 web_ics.conf 片段

```ini
client-ca = ./ics-certs/ca.crt
tls-cert = ./ics-certs/docs.example.com.crt
tls-key = ./ics-certs/docs.example.com.key
client-cert-deny = ./ics-certs/deny.txt
```

`client-ca` 是 web_ics 那侧唯一的开关。配了它却没配 `tls-cert`/`tls-key` 时服务会直接拒绝启动，
所以这四项是一组，缺哪项就注释掉哪项并写明原因。

### 6.4 构建相关

| 环境变量 | 作用 |
|---|---|
| `GOPROXY` | 脚本默认设成 `https://goproxy.cn,direct` |
| `VERSION` | 覆盖版本号（build.sh / build.ps1 的 `-Version`） |

## 七、依赖与构建

```
go 1.25.13

require (
    github.com/jchv/go-webview2   v0.0.0-20260205173254-56598839c808
    golang.org/x/sys              v0.10.0
    software.sslmate.com/src/go-pkcs12  v0.7.3
)
```

构建产物两个：`dist/web-ics-ca.exe`（交付物）与 `dist/web-ics-ca-linux-amd64`
（跨平台编译检查，不发）。三种构建方式与注意事项见 [README 的构建一节](../README.md#构建)。

**`build.ps1` 必须保持 UTF-8 with BOM。** 它里面有中文注释，而 Windows PowerShell 5.1
读无 BOM 文件时按系统 ANSI 代码页解码，UTF-8 汉字的末字节与 cp936 前导字节范围重叠，
会把紧跟其后的 ASCII 引号一起吃掉，报错却是「字符串缺少终止符」并落在文件末尾。
`build.sh` 里有一道守卫专门拦这个。

## 八、改动时容易漏的地方

| 改了什么 | 还要改 |
|---|---|
| `validate.Catalog()` 的字段说明 | `docs/字段说明与校验规则.md`（手工同步） |
| `FieldSpec.Key` | `ui/index.html` 里对应的 `data-help` |
| 校验返回的字段名 | `ui/index.html` 里对应的 `data-err` |
| `CertInfo` 的字段 | `ui/app.js` 的渲染，否则是死数据 |
| 接口名或入参 | `ui/app.js` 的 `api()` 调用点 |
| 证书参数（算法、KeyUsage、EKU） | 确认 web_ics 那侧还认；本项目目前没有自动化测试拦住这一点 |
| `build.ps1` 的内容 | 确认 BOM 还在（`build.sh` 会检查） |
| 新增平台相关能力 | 补一对 `*_windows.go` / `*_other.go` |

## 九、已知限制

- **`/api/reveal` 只在 Windows 上有效。** 它调的是 `explorer`，非 Windows 平台没有对应实现，
  `cmd.Start()` 失败被忽略，界面会显示成功但什么也没发生。启动流程有跨平台分支，这个接口没有。
- **`internal/app` 没有单元测试。** 目前靠端到端探测覆盖（起服务 → 建 CA → 签两种证书 →
  吊销 → 出配置），项目本身不带测试文件。
- **多显示器不同缩放比之间拖动**这条路径没有实测过。代码按 Per-Monitor V2 写的，
  理论上系统会让应用重新布局。
